# sawzan.com 全体設計(案) 2026-10-05

状態: 案。実装は、承認後に段階的に行う。静的サイト(GitHub Pages)で、サーバー側の処理・DBは持たない。

## 1. 目的と読み手
- 会社の信頼性(取引先・ストア審査・ユーザーが「ちゃんとした会社か」を見る)を示す。
- アプリごとの公式情報(案内・規約・プライバシー・削除申請)を、ストア審査にも使える形で置く。
- 法定の掲載先を置く(電子公告、将来は特商法)。
- 宣伝のための大きなサイトにはしない。更新頻度は低い前提。

## 2. 現状の棚卸し(2026-10-05)
| ページ | 役割 | 見た目 | 課題 |
|---|---|---|---|
| `/` | 会社の入口 | 専用のスタイル(山のヒーロー等) | 共通部品はヘッダー/フッターのみ |
| `/works/` | 作品・サービス | `/` と同系統 | 色などの定義が `/` と重複 |
| `/koukoku/` | 電子公告 | 別の簡素なスタイル | 会社ページと見た目が違う |
| `/enishiru/` | アプリ案内 | 別の簡素なスタイル | 同上。works にも載る予定で役割が重なる |
| `/enishiru/{privacy,terms,account-deletion}.html` | 法的・手続き文書 | 別の簡素なスタイル(文書向け) | ヘッダー無しでサイトに戻れない |
| `/privacy.html`, `/terms.html` | 旧URL→転送 | なし | 消さない(ストア登録・旧リンク) |
- スタイルが3系統(会社用/文書用/簡素)に分かれ、色・文字・ダークモードの定義が各ページに複製されている。

## 3. 方針
1. **見た目は2種類だけ**: 「会社ページ」(`/`・`/works/`)と「文書ページ」(規約・公告など、読みやすさ優先)。ただし、色・文字・ダークモードのトークンと、ヘッダー/フッターは共通にする。
2. **共通部品は1か所**: `assets/site.css`(トークン・基本スタイル・ヘッダー/フッター)と、`tools/build.py`(ヘッダー/フッターの差し込み、実装済み)。ページ固有のスタイルだけを各ページに残す。
3. **アプリごとにフォルダ**(現行どおり): `/{app}/index.html` が案内、配下に文書。URLは変えない。
4. **ビルドは軽く**: 依存なし(Python標準のみ)。コミット前に `build.py --check` で最新か確認する。
5. **JavaScriptは最小**: 作品一覧(`works.js`)のみ。それ以外は静的HTML。

## 4. 情報の構成(サイトマップ)
```
/                    会社トップ(事業内容・会社概要・沿革・お問い合わせ)
/works/              作品・サービス一覧(公開済みのみリンク)
/{app}/              アプリの案内(現在は enishiru)
  privacy.html  terms.html  account-deletion.html
/koukoku/            電子公告
/tokushoho/          特商法の表示(販売開始前に追加。noindex。承認後に公開)
/privacy.html /terms.html   旧URLの転送(維持)
```
- ヘッダーのメニュー: 事業内容 / 会社概要 / 沿革 / お問い合わせ / 作品・サービス →(`tools/build.py` の `MENU` で一元管理)。
- フッター: ©、電子公告、(販売開始後)特定商取引法に基づく表記、(必要なら)プライバシー。
- アプリ配下の文書ページは、軽いヘッダー(SAWZANのロゴ→トップへ戻る)+「えにしる」へのパンくずを付ける。

## 5. 実装の段階(それぞれ承認後に行う)
- **段階A(影響小)**: `assets/site.css` を作り、トークン・ダークモード・ヘッダー/フッターを集約。`/` と `/works/` を移行。見た目は変えない。
- **段階B**: 文書ページ用の共通スタイル(`doc` クラス)を作り、`/koukoku/`・`/enishiru/*` に適用。文書ページにも共通ヘッダー/フッターを入れる(`PAGES` に追加)。
- **段階C**: `/tokushoho/`(販売開始前)。登記後は、会社概要の更新。
- 各段階で、全URLが200であること、ダークモード・スマホ幅の見た目を確認し、`AGENTS.md` を更新する。

## 6. 守るもの(変えない)
- 既存URL(特に `/enishiru/privacy.html` と `/enishiru/terms.html`。ストアに登録するURL)と、旧URLの転送。
- 住所・実名・電話は、承認なしに載せない。「商標調査済み」とは書かない。
- 法定ページ(電子公告)は、noindex を付けない。noindex は特商法ページのみ想定(承認後)。
- Cloudflare/HSTS の注意(`AGENTS.md`)。

## 7. 決めたいこと
1. 文書ページ(規約など)に、会社サイトと同じヘッダー/フッターを入れてよいか。
2. `/enishiru/` と、`/works/` のえにしる(公開後)の役割分け(works=一覧と要約、`/enishiru/`=詳細、で提案)。
3. 段階A〜Cを、今すぐ進めるか、登記後にまとめるか。
